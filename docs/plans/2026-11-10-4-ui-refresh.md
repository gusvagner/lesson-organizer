# UI Refresh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A current look (Inter, rounded components, cobalt/navy palette, light and dark mode with a toggle, an app logo) and a drag-and-drop board as the Lesson plans main page.

**Architecture:** Design tokens live in `DESIGN.md` and become CSS variables plus Angular Material theme overrides in `frontend/src/styles/`. The board is a presentational component built on CDK drag-drop that emits the same `StatusChange` event as the old table; the page and `LessonPlanActions` stay the single place that saves. Status changes become optimistic in `LessonPlansStore` so a dropped card stays in its new column while the PATCH runs and returns on failure.

**Tech Stack:** Angular 22, Angular Material 22 (M3 theme API), CDK drag-drop, `@fontsource-variable/inter`, `material-symbols` (both from npm, approved by the human on 2026-11-10).

**Spec:** [DESIGN.md](../design.md) (binding for the look), the human's request of 2026-11-10 (board only, system theme + toggle, bundled fonts), [requirements.md §5](../requirements.md#5-user-interface-behavior), [frontend-architecture.md](../frontend-architecture.md).

## Global Constraints

- Pages and components use `--lo-*` variables or Material system tokens, never raw colors.
- Inter Variable and Material Symbols Rounded come from npm packages; `index.html` loads nothing from Google Fonts.
- Requirements still hold on the board: each card shows title, student, date and status; filters by student and status (the status filter shows only that column); cards sorted by lesson date ascending inside each column; empty states; status change disabled while saving.
- Dragging is never the only way to change status: each card keeps a status select (keyboard and screen readers).
- The board replaces the table and cards on `/lesson-plans` only; student details keeps its list of plans.
- Everything in English; no explanatory comments; tests named `<scenario> → <result>`.
- Commands from `frontend/`: `npx ng test --watch=false`, `npx ng build` (no warnings), `npx prettier --write src`.

## Review Focus

1. **Drop onto the same column** → no request, no snackbar. Test in Task 4.
2. **Drop while another save is running** → ignored (`saving`), the card returns. Test in Task 4.
3. **Failed PATCH after a drop** → the card returns to its old column and the error snackbar shows. Test in Task 3.
4. **Dark mode contrast** of status badges and muted text → values from DESIGN.md only. Checked in Task 5 by reading the tokens.
5. **Theme choice with blocked storage** (private mode) → toggle still works for the session, no error. Test in Task 2.
