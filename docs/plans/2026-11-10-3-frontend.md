# Frontend (stages 9–11) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Angular 22 app in `frontend/` that lets a teacher register, log in, manage students and lesson plans against the existing `/api`, covering workflows 1–3 of the requirements.

**Architecture:** Feature folders (`core/`, `shared/`, `features/auth|students|lesson-plans`). Pages talk to signal stores; stores talk to API services; only API services touch `HttpClient`. Presentational components take inputs and emit outputs. Same origin with the API through the dev proxy, so the Identity cookie and antiforgery work without CORS.

**Tech Stack:** Angular 22 (standalone, zoneless, OnPush, signals), Angular Material 22 + CDK, typed reactive forms, Vitest (CLI default runner), `HttpTestingController`, named fakes.

**Spec:** [frontend-architecture.md](../frontend-architecture.md) (binding for structure, routes, data flow, auth, UI states, tests), [requirements.md §5–6](../requirements.md#5-user-interface-behavior), [plan.md §5 API contracts, §6 Frontend criteria, §7 stages 9–11](../plan.md), [stack.md Frontend](../stack.md#frontend).

## Global Constraints

- Everything in English: UI text, code, commits.
- Angular 22 and Angular Material 22, created with the project-local CLI (`npx @angular/cli@22`); exact versions come from `package-lock.json`, which is committed. No other npm packages.
- No NgRx or other state library, no NgModules, no `zone.js`, no CSS framework, no date library, no mocking library.
- Components: standalone, `ChangeDetectionStrategy.OnPush`, signal `input()`/`output()`, `@if`/`@for` control flow, one component per file.
- File naming follows the Angular v20+ style guide (no `.component`/`.service` suffixes): `login-page.ts` holds `class LoginPage`; models keep `.model.ts`; tests are `<file>.spec.ts`.
- Forms are typed reactive forms (stack.md). Client limits mirror the backend: name 150, email 254, notes 2000, title 150, description 5000, password 8–128. The backend stays the authority.
- `lessonDate` is a `yyyy-MM-dd` string in every model; never `new Date('yyyy-MM-dd')`.
- Enum values are string unions: `EnglishLevel = 'Beginner' | 'Elementary' | 'Intermediate' | 'UpperIntermediate' | 'Advanced'`, `LessonPlanStatus = 'ToPrepare' | 'Ready' | 'Delivered'`.
- Optional request strings (`email`, `notes`, `description`) are sent as `null` when blank.
- XSRF: cookie `XSRF-TOKEN`, header `X-XSRF-TOKEN`; stale-token problem type `urn:lesson-organizer:problem:invalid-xsrf-token`.
- Copy pinned by the spec: "Not found", "Something went wrong. Try again.", "Student saved", "Student deleted", "Lesson plan saved", "Lesson plan deleted", "Status changed to <label>", "Add your first student", "Create a student first", "No results", "Clear filters", "New lesson plan", "No lesson plans yet".
- Test naming: `describe('<unit>')` + `it('<scenario> → <expected result>')`.
- No explanatory comments in code.
- Commands run from `frontend/`: tests `npx ng test --watch=false`, build `npx ng build`.

## Review Focus

1. **Crafted `returnUrl`** (`//evil.example`, `https://evil.example`, `javascript:...`): after login the user lands on `/lesson-plans`, never another site. Test in Task 4 (`safeReturnUrl`).
2. **Unknown query values** (`/lesson-plans?status=Done&studentId=abc`): the page ignores them and loads the unfiltered list instead of showing an error. Test in Task 8.
3. **Opening a deleted or another teacher's record by URL** (`/students/<id>`, `/lesson-plans/<id>/edit`): the user sees "Not found" and lands on the list, not an empty form. Tests in Tasks 7 and 8.
4. **Whitespace-only name or title**: shown as "Name is required." / "Title is required." under the field before any request. Tests in Tasks 7 and 8 (`notBlank` validator, Task 2).
5. **Search text with `%`, `&`, `#` or spaces**: sent URL-encoded in `search`, and an empty search sends no `search` parameter. Test in Task 5.
